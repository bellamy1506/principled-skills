# Origins: why each rule is there

Read this when a rule in SKILL.md looks arbitrary. Each rule came from
something that happened when councils were run on real work: about twenty
in one multi-agent project, and later runs from this skill. This is a
summary of those events. The skill does not depend on any of those
projects.

| Rule | What happened |
|---|---|
| A goal set high | The first council was given a time for a test suite that the owner had named on the assumption that it could not be met. The result beat it. |
| A goal not reached is a normal result | Most councils with such a goal did not reach it. Each ended with a measured distance and the reason for it, and each still landed gains. |
| One goal, several routes | Some councils were given one task for each member and no shared number. A review found that a member had built what a single agent could have built alone. The owner: members are not to be merely named or tasked differently; one goal, several approaches, so the best of each can be taken. |
| Routes that worked | One number, three routes: run less, run faster, run at a better time. |
| Fence the neighbour's lever | Overlapping route text produced the same new mechanism twice and two tunings of the same setting. |
| Baseline alone, facts with commands | A base number given in a brief did not reproduce, and every member measured it again. |
| Find where the number comes from | A council was aimed at a part of the project that held a small fraction of the number. No effort there could have reached the goal. |
| A guard on the goal; protect the measure | A score was measured on the same cases it was tuned on. Headline numbers were taken with settings that real use did not have. Several new checks could not fail. |
| A limit is a loop detector | The owner, on a proposed cap: raise it so that it catches loops and not good work; hard problems sometimes need the same wall hit many times. One member later repeated a whole-suite run many times; its route cost the most and landed nothing. |
| A fast measure | Slow, repeated full runs were the largest cost of a member. Unrelated heavy work at the same time made timings worthless. |
| Research between rounds | From the first council: after one independent round, a member can request evidence that lets it go further, and then continues. |
| Stack and measure again | An integrator found faults that appeared only when routes were combined. Several members had made the same new file. |
| Policy choices go to the owner | Which of two valid designs wins was never left to an integrator. |
| The stress round is not optional | The owner: the work is not done until it has been attacked for edge cases and gaps. The first such round found about thirty problems behind a passing suite. |
| Two attackers, separate ground | Attackers given shared ground found the same defects more than once and cost about twice what two would. |
| Sort findings with sense | The owner: do not slow development or add cost to prevent a rare, harmless oddity. Security is the exception. |
| A panel feeds a council only through its synthesis | A panelist is bent on purpose. Its report is material for a synthesis, not a build plan. |
| Mechanical integration by script | Integrating and tallying by hand made orchestration cost as much as the members. |
| One agent, not a council | Councils given an edit, a survey or a reading cost more for each finding than those that ran something real, and found less. |
| The script reports a changed measure file | During a council, the orchestrator changed inputs of the measure in the project itself, for other work. The members' copies kept the old measure, and the result table carried a column corrected by hand. |
| The script records load and cores | Builders and unrelated agents shared a small machine. A check failed at random and a full measure took twice its time. |
| The script says when there is no final number | A combined result was measured once, before the stress round. The fixes went to later work. Only the report's candour showed that no final number existed. |
| `--protect` once for each glob | A run's notes recorded a limit of one glob. The flag always repeated; the text showed one. |
| A pick between alternatives waits for the corrected numbers | All routes changed the same lines, so one was picked. The gap between them was how far each used a device that the stress round then disproved. Without that part the routes were level. The pick was not opened again. |
| Compare the largest parts with the owner's recorded decisions | The largest part of a baseline was a state the owner had already decided to keep. Each member's first and largest gain was there, and it was put back afterwards. |
| Routes from elsewhere are candidates | A ticket carried routes written before the measure existed. Two overlapped. The orchestrator saw it and kept them because they were the ticket's. Nothing stacked. |
| A proposal says if the measure exists, what was tried, and who shares the machine | A council was approved before its measure existed and before anyone had tried the number. Every member then covered most of the distance in a few mechanical steps. |
