# Origins: why each rule is there

Read this when a rule in SKILL.md looks arbitrary. Each rule came from
something that happened when panels were used on real work, over several
months of multi-agent projects. This is a summary of those events.
The skill does not depend on any of those projects.

| Rule | What happened |
|---|---|
| Three far-apart lenses | The first panel was three specialists with different priorities, asked to grade work its author could not judge. They gave the same grade. The finding that changed the project came from one lens alone: a large body of prose rules had caught no defects. |
| Synthesis, not consensus | Early text told the panel to reach a consensus, and the first draft of this skill was built on that. The owner corrected it: the purpose was never agreement. Models converge on their training, and forced, different premises let a problem leave the ruts that limit its solutions. A lens set on a poor road can still bring back something nobody else would find. |
| A panelist does not implement | A lens gives up general balance for a specialist's reach. None of the three would be trusted to build alone. |
| The class lens | After a round of fixes, a fresh panel gave the same grade again: the reported cases were fixed and their classes were not. |
| A lens can relocate the question | One panel judged the orchestrator's framing to be in the wrong place and moved the boundary to somewhere nobody had proposed. |
| Front-loaded cost; not a routine loop | The owner treats a panel as a cost paid early to reduce later intervention, with the aim that panels become unnecessary. Unattended runs do not start one. |
| The cheap model; a stronger one only at the owner's request | A round on a stronger model cost about as much as the dearest round on the cheap one and found the same kind of thing. The value comes from the difference between reviewers. |
| Name the model | An unnamed model inherited the orchestrator's, and the round cost about three times what it needed. |
| Evidence, not conclusions | A hypothesis written into a brief came back from all three reviewers. Later, an "independent" finding was traced to a cause named in one reviewer's lens text. |
| A fresh reader must not fall into your reasoning | The owner asked for briefs a fresh specialist would understand fully without inheriting the orchestrator's earlier reasoning, and for work already done to be hidden where it would anchor the reader. |
| Verify facts before you use them | Reviewers were confidently wrong in both directions: a duplicate that a search refuted, two checks called redundant that covered different cases, a count low by more than half. |
| Agreement on a method is not agreement on a fact | Three reviewers agreed that a file did not exist. All three had searched the same two directories. It existed. |
| A reviewer is a clever junior developer | The owner's instruction: a reviewer may be exactly right, or may have a good idea badly built. Verify; do not assume the cleanest implementation was offered. |
| Unresolved tension goes to the owner as a choice | Two lenses disagreed on whether a safeguard cost more than the work it guarded. The report left it open, with both positions and a recommendation. |
| The cross-pollination round | One panel ran further rounds in which reviewers saw each other's reports. Every position that moved did so because another reviewer supplied evidence. Disagreements about what matters did not move. The rounds added about 60% to the cost. |
| Fresh reviewers for a re-grade | A reviewer that grades its own suggested edit is not independent. |
| Stop at a plateau | Repeated scoring rounds returned nearly the same score, each naming a few new small items. |
| A read-only agent type, not only a sentence | A rule that is only a sentence fails. The reviewer type has no edit or write tool. |
| Panels think, councils do | A council member builds and experiments in its own copy toward a goal. That role is never a read-only reviewer. |
| A fix made on a panel's word still needs its own check | A fix adopted from a panel finding introduced a fault of its own. |
| Check the instrument before dispatch | Three panels in a row stood on a stand-in for the real thing: automatic checks that did not agree with a person's judgement, a sandbox with no reading from the real device, and test pages that did not render as the real screen did. In one, two reviewers reported a defect that the real screen did not have. |
| Everything written for a reviewer is a leak channel | Two lens paragraphs made one claim in different words, and a question shared by all three listed its answer. All three reports recommended that answer first, and the synthesis called it agreement from different starting points. |
| The dispatch block with expected headlines | Panels gave the owner one sentence at dispatch: no goal line, no line for each lens, no cost. Matching lens premises would have been visible side by side. |
| A proved discovery from any source can open the second round | An orchestrator measured the real device during round one and did not weigh a second round. A cheaper fix, which a lens holding that measurement could have reached, was found only later. The owner: an important finding from the orchestrator counts for giving to the reviewers. |
| Evidence that only removes a finding opens no round | Evidence from the owner removed two findings and opened no new line of attack. The findings were measured again and dropped. |
| What a saved round holds | A project's record form dropped several report sections that the chat report had. No panel saved its briefs, so a later review could find a brief leak only in a transcript. |
| Hand-off routes are candidates | A panel's routes went word for word into a ticket and then into a council. Two overlapped, the builders edited the same lines, and nothing could be stacked. |
| The reviewer type is installed before the session | Sessions on a fresh machine had no reviewer type. Reviewers ran on a built-in planning agent, and every report ended with that agent's own closing section. |
| State the expected cost at dispatch | Rounds in which reviewers ran measurements or web research cost up to about twice a reading round. |

## Rules that were removed. Do not restore them

- "Panel cost is excluded from efficiency arithmetic." It argued for not
  counting a front-loaded cost, never for spending more than the result
  needs.
- "Panels are the largest single expense." A panel on the cheap model costs
  a few dollars.
- "Reconcile into a consensus" as the goal of the round. See the synthesis
  row above.
